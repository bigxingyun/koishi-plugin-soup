# 让 AI 按汤调整版面：可行，但只能调「编辑决策」

## 结论

**能做，而且值得做；但不能把整页 HTML/CSS 交给 AI 写。**

正确切法是：把模板「翻译」成一份 **`LayoutPlan` JSON 契约**，AI 只输出这份 JSON（引题、副题、段落切分、字号、栏数、主色、印章文字），**我们按 JSON 确定性地渲染**。

- 好处：版式永远不塌，风格永远统一，出问题可回滚到默认 plan。
- 不这么做的后果：每锅汤一张陌生脸，AI 偶尔吐出 `style="..."` 把版心撑爆，你还得为每张图人工擦屁股。

`build.py` 已经是这个形态的参考实现：读 plan → 校验/夹紧 → 填模板 → 出 HTML。

## 该交给 AI 的 / 不该交给 AI 的

| 决策 | 交给谁 | 理由 |
| --- | --- | --- |
| 引题（kicker）、副题（deck） | **AI** | 这是纯写作，模型比模板生成器强得多，直接决定「想不想读」 |
| 段落怎么切、哪句做小标题 | **AI** | 长汤面切成 2~4 段的节奏感，人工写死只能覆盖一种 |
| 主色（rust/blood/ink/steel） | **AI 选枚举** | 「这锅汤是恐怖还是冷案」模型判断得准，但只能四选一 |
| 印章文字（≤4 字） | **AI** | 「本报独家 / 绝密 / 号外」值得随汤变化 |
| 字号、栏数、行距 | **代码算** | 由字数与版心决定，AI 给的数字只会越界 |
| 任何 CSS / HTML / 颜色值 | **禁止** | 一条 `position:fixed` 或外链字体就能毁掉整页，还带 SSRF 风险 |
| 汤面原文 | **禁止改写事实** | 只能改标点、分段；加一句原文没有的细节就等于泄底或误导 |

## 契约

Schema：[`layout-plan.schema.json`](layout-plan.schema.json)　示例：[`plans/01-additive-harm.json`](plans/01-additive-harm.json)

```json
{
  "version": 1,
  "kicker": "越吃越买　越买越怕",
  "title": "添加剂危害",
  "deck": "街坊们一边抓挠、一边瞪眼、一边排着队，把三周里的每一个样品都买了回去",
  "body": ["我家开了个小吃摊。第一周：…", "第二周：…", "第三周：…"],
  "style": { "columns": 2, "accent": "rust" },
  "stamp": { "text": "本报独家", "angle": -8, "opacity": 0.6 }
}
```

字段中只有 `title`、`body` 是必填，其余可缺省——缺省就用模板默认值。

## 直接可用的 prompt

```text
你是《海龟汤晚报》的排版编辑。给你一锅海龟汤，你要产出一份「版面规划」JSON，
让这锅汤被印成一张做旧报纸的号外。

【汤名】{title}
【难度】{difficulty}　【标签】{tags}
【汤面】
{surface}

【你要产出】
{
  "version": 1,
  "kicker": "引题，≤18 字，制造悬念，不要复述汤面",
  "title": "主标题，≤14 字，默认沿用汤名",
  "deck": "副题，≤48 字，一句话点出最反常的冲突，但不能说出答案",
  "body": ["按原文切分成 1~6 段，段内只允许调整标点与换行"],
  "style": { "accent": "rust | blood | ink | steel", "columns": 1 或 2, "dropCap": true },
  "stamp": { "text": "2~4 个字的印章文字" }
}

【accent 选择标准】
- rust  铁锈红：社会派、日常崩坏、细思极恐
- blood 暗红：血腥、暴力、恐怖
- ink   墨黑：本格推理、旧案、冷峻
- steel 钢蓝：刑侦、悬疑、多方说法冲突

【硬性约束】
1. 只输出 JSON，不要解释，不要代码块。
2. 禁止改写事实：不得增加汤面里没有的人物、地点、物品、因果。
3. 禁止在 deck / kicker 里说出真相、凶手、关键手法。
4. 不得输出任何 HTML、CSS、颜色值、URL。
```

## 三道防线

1. **Schema 校验**：`additionalProperties: false`，多余字段直接丢弃；`enum` 只收白名单。
2. **数值夹紧**：`build.py` 的 `clamp()` 会把字号夹进 `[12, 16.5]`、行距夹进 `[1.65, 2.1]`、印章角度夹进 `[-12, 0]`，越界记 WARN 而不是崩溃。
3. **默认回退**：模型超时、返回非 JSON、字段全错 → 直接用从汤数据推导的默认 plan。**玩家永远看到一张报纸，看不到报错。**

## 成本与延迟：关键在「预生成」

**不要在 `开局` 时调模型。** 一局多等 2 秒，而同一锅汤会被玩几十次。

| 时机 | 做法 | 代价 |
| --- | --- | --- |
| 汤库导入时（离线） | 逐锅生成 plan，存进 `tale.newspaper` 字段 | 一次性，可批量、可失败重试 |
| 第一次 `开局`（兜底） | 若该汤没有 plan，现生成并落库 | 仅一次，之后命中缓存 |
| 之后每次 `开局` | 直接读 plan → 渲染 | **0 次模型调用** |

以 `deepseek-flash` 空闲时段计费，一锅汤的 plan 生成（输入约 600 tokens、输出约 400 tokens）成本 ≈ **0.002 元**，一次性。
所以「按汤自动调版」的成本约等于 0，真正贵的是判词。

## 三个容易踩的坑

1. **别让模型算排版**。问「用几栏」它答得头头是道，但页高一溢出就废了。字数→字号的映射交给代码，AI 只给风格倾向。
2. **`deck` 最容易泄底**。「她死于一场精心策划的报复」——副题就把答案说了一半。prompt 里必须显式禁止，并加一道人工抽检。
3. **缓存要带模板版本号**。模板改了（比如 masthead 字号），旧 plan 渲染出来的图会变，但缓存还在。缓存键用 `sha1(taleId + taleVersion + planHash + TEMPLATE_VERSION)`，模板一改就整体失效。

## 验收怎么做

- **快照测试**：把 `plans/*.json` 当作固定输入，渲染结果与基线图逐像素比对。AI 有随机性，所以**测试只跑固定 plan，不跑 live 模型**。
- **契约测试**：给模型 20 锅汤，统计 JSON 一次解析成功率（目标 ≥ 98%）与字段越界率（目标 ≤ 5%）。
- **抽检**：每锅新汤的 `deck` 人工看一遍，确认没泄底。

## 已知限制

- `build.py` 用「字数阈值」估字号（`<280` 放大、`>800` 缩），只是近似。**插件里应改成渲染后量高度**：`page.$eval('body', el => el.scrollHeight)`，超过 `renderMaxHeight`（建议 2400px）再降一档，最多 2 次。
- 汤面里的 Markdown 结构（`## 标题`、表格、引用）目前不支持，需先转成纯段落。`汤/血色墓穴.md` 就是这种，样张 03 是人工整理后的文本。
- 中文断行由浏览器决定，不同字体度量会差 1~2 个字，**不要**在 plan 里写死任何像素位置。
